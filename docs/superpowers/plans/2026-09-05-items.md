# Items (Plan 2D) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add Equipment (3 swappable slots), Relics (permanent, unlimited,
stacking), Potions (2 combat-only slots), and reintroduce Treasure nodes —
the third and final sub-project of Plan 2.

**Architecture:** Three new plain-data `Resource` classes
(`EquipmentResource`, `RelicResource`, `PotionResource`) plus hand-authored
Dwarf content files, mirroring `SkillNode`/`DwarfSkillTree`'s shape exactly.
`RunState` gains three independent bonus-tracking sections (Equipment,
Relics, Potions) that all funnel into `build_encounter_for_node` through
the same additive, build-time-only channels Plan 2C proved safe
(`baseline_strike_bonus`, `baseline_block_bonus`, status stacks,
`starting_block`) — plus one generalization: a shared `_apply_passive`
helper replaces the two hardcoded `.has("battle_fury")`/`.has("unyielding")`
checks, so Equipment's Trinket passives reuse the same dispatch instead of
adding a third hardcoded check.

**Tech Stack:** Godot 4.7.stable, GDScript (strict typing throughout), GUT
9.6.1 for tests.

**Spec:** `docs/superpowers/specs/2026-09-05-items-design.md`

## Global Constraints

- Every `var`, parameter, and return type is explicitly typed (project
  convention, no exceptions).
- Tests drive the same entry point a real click would (emit the button's
  `pressed` signal, or the view's own public signal) — never call a
  private `_on_*` handler directly.
- `RunState` is a shared autoload singleton — every test that reads or
  mutates its state must call `RunState.start_new_run(...)` first.
- **Any test asserting on a value the combat turn loop can touch
  (`block`, `starting_block`, anything set by a passive) must call
  `encounter.start_player_turn()` before asserting** — a test that only
  checks state immediately after `build_encounter_for_node` proved
  nothing in Plan 2C and shipped a dead capstone. This is not optional
  polish; it is the single most important lesson this plan carries
  forward.
- Equipment never touches `player_max_hp` — only Strength/Block bonuses
  and the two shared passive ids, since equipment is swappable and a
  permanent HP bake-in would need to "un-bake" on unequip.
- No new turn-loop hooks beyond what Plan 2C already added
  (`CombatActor.starting_block`, consumed once by
  `CombatEncounter.start_player_turn()`). Potions are the one deliberate
  exception — they act on a *live* `CombatActor` during an active turn,
  the same way playing a card does, and are explicitly in scope.
- No rarity tiers, no weighted drop tables, no equipment upgrade/enchant
  system, no relic/equipment slot caps beyond the 3 named Equipment slots
  and the 2 named Potion slots.
